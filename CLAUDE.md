# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Build & Development Commands

```bash
# Install dependencies
pnpm install

# Development (all apps/packages)
pnpm dev

# The app as one brand (reads apps/backoffice/.env, then .env.so or .env.fm)
pnpm dev:so   # BRAND=SO on http://localhost:3000
pnpm dev:fm   # BRAND=FM on http://localhost:3001

# Build all
pnpm build

# Lint all
pnpm lint

# Type check all
pnpm check:types

# Run tests (unit + Storybook browser tests, needs `pnpm --filter @cbt-bo/portal exec playwright install chromium` once)
pnpm test

# Storybook
pnpm storybook
pnpm build:storybook

# Format and auto-fix lint (run before committing)
pnpm tidy
pnpm tidy:app  # the app only, also type checks
```

### Package-Specific Commands

```bash
pnpm --filter backoffice build
pnpm --filter backoffice test
pnpm --filter @cbt-bo/portal storybook   # component stories on http://localhost:6008
pnpm --filter @cbt-bo/config build       # rebuild shared presets after editing packages/config
```

### API Codegen

`packages/api-schema` holds the orval-generated MGT clients. Regeneration needs the spec URLs from its `.env.example` in a local `.env.local`.

```bash
pnpm --filter @cbt-bo/api-schema gen:api:build         # both targets, then build
pnpm --filter @cbt-bo/api-schema gen:api:build:bo-fm   # FM backoffice only
pnpm --filter @cbt-bo/api-schema gen:api:build:bo-so   # SO backoffice only
```

### TanStack CLI

The app was scaffolded with `@tanstack/cli create` and keeps its `.cta.json`. Add an integration from the app directory and review the regenerated files with `git diff`:

```bash
cd apps/backoffice
pnpm dlx @tanstack/cli@latest create --list-add-ons
pnpm dlx @tanstack/cli@latest add <id>
```

## Architecture

This is a **Turborepo monorepo** using pnpm workspaces.

```
cbt-backoffice/
├── apps/
│   └── backoffice/       # the admin portal app (TanStack Start), brand chosen by BRAND at runtime
└── packages/
    ├── api-schema/       # orval-generated MGT API clients (bo-fm, bo-so) and the fetch mutator
    ├── config/           # shared configs (eslint, typescript, prettier, vitest, storybook)
    └── portal/           # the admin portal itself: pages, layouts, hooks, stores, i18n, shadcn/ui
```

### App

`apps/backoffice` is a thin [TanStack Start](https://tanstack.com/start) shell on React 19, Vite 8, and Nitro. One build serves both brands: `BRAND` (`SO` or `FM`) is read from the server environment on every request and registered through `setEnv`, so `isBrandSo()` and the brand tokens are runtime decisions.

- File-based routes live in `src/routes`. `src/routeTree.gen.ts` is generated by the router plugin and committed. Regenerate it with `pnpm --filter backoffice generate-routes` after adding a route file.
- Route files are thin. A page route imports its component from `@cbt-bo/portal/pages/<name>` and passes it to `createFileRoute`. List pages parse their own search params with `useListSearch`, so routes declare no `validateSearch`. Dynamic routes pass params as props, for example `players_.$id.tsx` renders `<PlayerDetailPage playerId={id} />`.
- `src/routes/__root.tsx` loads the runtime env through the `getRuntimeEnv` server function in `src/server/runtime-env.ts` (`BRAND`, `MGT_BASE_URL`, `MGT_SITE_ID`, `CLIENT_SITE_LOCALES`, see `.env.example`), derives `<html data-brand>` and the portal name from it, and wraps the app in `PortalProviders` and `AppLayout` from `@cbt-bo/portal/app`. An unknown `BRAND` fails the loader.
- Local development keeps the shared values in `.env` and the per-brand ones in `.env.so` / `.env.fm`. `vite.config.ts` loads the `--mode` env files into `process.env` so the Nitro dev server sees them.
- Server routes use `createFileRoute` with `server.handlers`, for example `src/routes/api/health.ts`.
- `#/*` resolves to the app's `src/*`. `~/*` resolves to `packages/portal/src/*` and is the alias used inside the portal package.
- `src/styles.css` imports `@cbt-bo/portal/styles.css` and registers the package source with `@source` so Tailwind sees its classes.
- TanStack Query is wired through `src/integrations` and the router context.
- `vite build` produces `.output/`; `node .output/server/index.mjs` starts the server on `PORT`. The output is self-contained. `traceDeps: ['react', 'react-dom']` in `vite.config.ts` copies both packages into `.output/server/node_modules` for the `use-sync-external-store` shim's runtime `require("react")`, and `.github/scripts/smoke-test-output.sh` verifies the app boots from a directory outside the workspace.
- Vitest config lives in the `test` field of `vite.config.ts` via `createTanstackStartTestConfig`.

### Portal package

`packages/portal` (`@cbt-bo/portal`) is consumed as TypeScript source. Its layout:

- `src/app` exports `PortalProviders`, `AppLayout`, `ColorSchemeScript`, and `buildPortalHead` for the root route.
- `src/pages/<name>` holds one page: `use-<name>.ts(x)` (queries, mutations, columns, search fields), `<Name>Page.tsx`, its forms, and an `index.ts` barrel. List pages keep search and pagination in the route search params through `useListPage`, which builds the zod schema from the search fields.
- `src/table` holds the TanStack Table v9 primitives. `useListPage` + `ListPage` render a server-paginated page, `EmbeddedList` renders a list inside another page with `isRouteBound: false`, `buildTableConfig` derives columns and detail rows from a `columnsOrder` tuple plus `fieldOptions`, `buildActionsColumn` adds the row action buttons, and `selection` on `useListPage` enables the checkbox column.
- `src/forms` holds the TanStack Form composition. `useAppForm` registers the field components (`TextField`, `NumberField`, `SelectField`, `ComboboxField`, `MultiSelectField`, `DateTimeField`, `SwitchField`, `CheckboxField`, `TextareaField`, `RichTextField`, `LocaleValuesField`, `RichTextLocaleValuesField`, `ImagesField`, `ExpressionField`, `PasswordField`) and the form components (`FormShell`, `SubmitButton`). Validation is zod through `validators: { onSubmit: schema }`, and the schema input type must match the form values exactly.
- `src/hooks` holds the page building blocks: `useFormDialog` (create/edit dialog state), `useSaveMutation` (mutation plus toast plus invalidation), `useConfirmDialog`, `useBlobExport` and `useExportJob` (downloads), `useFileUpload`, `usePagePermission`, `useDisclosure`, `useDebouncedCallback`.
- `src/store` holds `@tanstack/react-store` stores. Persisted ones go through `persistStore`.
- `src/services/mgt.ts` wraps generated API functions as actions that throw `ApiError`. `src/actions` and `src/queries` build on it.
- Styling is Tailwind CSS v4 with shadcn/ui components under `src/components/ui` (vendored, excluded from lint). `src/styles.css` is the Tailwind entry and holds the brand tokens.

### Internal Dependencies

Packages reference each other via `workspace:*` under the `@cbt-bo/*` scope. The app depends on `@cbt-bo/config` (built by tsdown on `postinstall`), `@cbt-bo/portal` (raw source), and through it `@cbt-bo/api-schema` (built by tsdown, run `pnpm build` after regenerating). Every package is `private` and the only `version` field lives in the root `package.json`.

## Build & Deploy

- The root `Dockerfile` copies only `apps/backoffice/.output/` onto `node:24-alpine`. Nothing is installed or compiled inside Docker, and the same image serves both brands through the `BRAND` environment variable.
- `.github/workflows/build.yaml` builds `ghcr.io/codingbrostech/cbt-backoffice:sha-<commit>`, and the `so-bo-*` / `fm-bo-*` workflows deploy one brand by re-tagging it. `docs/deployment.md` has the tag format, the `cbt-deploy` settings, and the cutover plan from `cbt-play-web`.
- `pr-checks.yml` runs `pnpm turbo run lint check:types test`, `pnpm build`, and the standalone smoke test on every PR.

## Code Standards

- **ESLint**: Zero warnings policy (`--max-warnings 0` in every `lint` script). Presets from `@cbt-bo/config/eslint` combine the repo rules with the TanStack toolchain (`flat/tanstack`, `flat/router`, `flat/react-query`).
- **TypeScript**: Strict mode enabled, `verbatimModuleSyntax`
- **React**: Version 19

Repo-wide writing and coding conventions live in `.claude/rules/`. See `writing-style.md` for prose and documentation style, and `coding-conventions.md` for test naming, comments, and code structure.
