# SearchBar

The filter bar above a list page. It shows the page title with an optional action at the end, then a row of filter fields with reset and search buttons. Searching hands the field values to the page, which puts them in its list query.

<Canvas of={SearchBarStories.Default} />

## Usage

`SearchBar` is a set of parts. Always nest them like this. The values go to `Root`, each field part binds to one of them by `name`, and every part takes only the labels it shows.

```tsx
<SearchBar.Root defaultValues={DEFAULT_FILTER} values={filter} onSubmit={search}>
  <SearchBar.Header title="Admins">
    <Button type="button">Create Admin</Button>
  </SearchBar.Header>
  <SearchBar.Fields>
    <SearchBar.TextField name="code" label="Login" />
    <SearchBar.SelectField name="state" label="State" options={stateOptions} allLabel="All" />
    <SearchBar.SelectField name="role" label="Role" options={roleOptions} allLabel="All" />
    <SearchBar.MultiSelectField
      name="labelIds"
      label="Labels"
      options={labelOptions}
      removeLabel="Remove"
      allLabel="All"
    />
    <SearchBar.Actions resetLabel="Reset" submitLabel="Search">
      <SearchBar.ViewToggle
        label="View"
        value={view}
        options={viewOptions}
        onValueChange={setView}
      />
    </SearchBar.Actions>
  </SearchBar.Fields>
</SearchBar.Root>
```

`Root` holds the draft values in a react-hook-form instance and shares it through `FormProvider`, so the field parts need no `control` prop. The page owns the applied filter. Searching calls `onSubmit` with the draft values, and resetting returns every field to `defaultValues` and calls `onSubmit` with them. When the page passes `values`, the fields follow them whenever they change, so a filter applied from elsewhere shows in the bar.

## Values format

`defaultValues` and `values` share one shape, an object with a string per field, or a string array for a `MultiSelectField`. An empty string or an empty array means the field is not applied. The page strips blank fields before building its query.

```tsx
export interface IAdminListFilter {
  code: string;
  state: string;
  role: string;
}

export const DEFAULT_ADMIN_LIST_FILTER = {
  code: '',
  state: '',
  role: ''
} as const satisfies IAdminListFilter;
```

## How the bar shows

The fields sit in a grid of equal columns at least 10rem wide and wrap onto more rows when the panel narrows. The buttons stay at the end of the last row. Without children, `Header` shows only the title.

## Usage in the app

Render it above `DataTable.Root` in a list page. The page keeps the applied filter beside the page params, and its list hook returns to the first page on every search.

```tsx
import { ACTIVATION_STATES } from '@cbt-bo/api/common/constants';
import { DEFAULT_ADMIN_LIST_FILTER } from '@cbt-bo/api/admin/queries';
import { SearchBar } from '@cbt-bo/component-lib/components/search';

const { filter, search } = useAdminList();
const stateOptions = ACTIVATION_STATES.map(state => ({ value: state, label: t(`state.${state}`) }));

<SearchBar.Root defaultValues={DEFAULT_ADMIN_LIST_FILTER} values={filter} onSubmit={search}>
  <SearchBar.Header title={t('nav.admins')}>
    <Button type="button" onClick={openCreate}>
      <PlusIcon />
      {t('admins.create')}
    </Button>
  </SearchBar.Header>
  <SearchBar.Fields>
    <SearchBar.TextField name="code" label={t('admins.code')} />
    <SearchBar.SelectField
      name="state"
      label={t('admins.state')}
      options={stateOptions}
      allLabel={t('common.all')}
    />
    <SearchBar.Actions resetLabel={t('common.reset')} submitLabel={t('common.search')} />
  </SearchBar.Fields>
</SearchBar.Root>;
```
